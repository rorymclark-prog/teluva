What it does

Four things, done properly.

Built against one household's real records — not a demo dataset — and then made to work for a small business too.

File

Photograph a document. It's read, filed to the right person and the right category, and the expiry date goes in the calendar.

Find

Ask in plain language. Answers come from your own records — never from a guess.

Share

Gather exactly what a clinic, a school or an insurer needs into one folder. Nothing more travels with it.

Keep

Wills, directives and where the signed original physically is — held under their own lock, released only while you're there to see it.

File

The paperwork files itself.

Photograph a passport, a vaccination card, a rental contract. It's read, matched to the person it belongs to, and filed under one of seven categories — with the expiry date lifted out and put where you'll see it coming.

  • Nothing is written until you tap Apply. Every extraction arrives as a proposed change you can read, edit or throw away.
  • Five countries have their own ID field sets — Austria, South Africa, the UK, the US and Romania — with the national emergency number for each, individually sourced.
  • Duplicates are caught by content, so the same scan filed twice from two phones is one document.

Find

An assistant that can't make things up.

Ask when the passport expires, what she's allergic to, or which documents are on file for whom. The answer comes out of your own records. When it reads a document back to you, the words are cut out of the real page by the server — the model never gets to author them.

  • It never says a document doesn't mention something. A bad scan, a blank field and a genuinely absent clause look identical from the inside, so it only ever reports what it found.
  • It never interprets. No legal, medical, tax or funeral advice — with a one-tap handoff to open the document in your own AI app if that's what you actually want.
  • Text inside a scan is data, not instructions. A page that reads "ignore previous instructions" gets flagged, not obeyed.

Share

One folder, with exactly what they asked for.

"Gather everything medical for Mia." You get a folder: the records, the scans, and a written summary you can hand to a new paediatrician — as a PDF for the receptionist, or as Markdown for whatever you want to read it with.

  • Fifteen topics, picked individually or as a bundle, so a school folder never quietly contains an MRI.
  • The assistant chooses topics; it never touches the files. It can be wrong about the selection — which you see and correct before anything leaves the device — but it cannot be wrong about the contents.
  • Nothing is silently dropped. An empty topic and a record with no scan attached are both reported, so "everything" is a claim you can check.

Keep

The will, and no trapdoor.

Where the signed original physically is. Who to call. What's been said out loud and what hasn't. Held behind its own lock — not visible to everyone in the household just because they're in the household.

  • There is no death trigger. Nothing in this app opens on someone dying. Access changes hands one of two ways, both while you're alive: you release it, or a person you named asks and it opens after seven days if nobody with standing objects.
  • Named readers, not blanket access. An admin names who can read it. Being family isn't the qualification.
  • It records; it does not advise. It will never suggest who to name, and never write your letter for you — only store, word for word, what you dictate.

And at work

The same filing, for a small team.

A business space keeps a roster instead of a family: who works here, on what basis, and which of their certificates is about to run out. The filing works the same way; the boundaries do not.

  • An employer is not next of kin. Employee records hold what an employer legitimately needs and stop there — a colleague's home life is not a tab you can open.
  • Owner, manager, employee, contractor are separate standings, and each one sees a different amount.
  • CVs, qualifications and expiry dates export as one pack when an inspector, a client or a funder asks.

Security

What we can see, and what we can't.

Everything below is enforced in the database rules or the server code, not in the interface. Hiding a tab in the app protects nothing.

Sensitive numbers are encrypted before they're stored

Passport and national ID numbers, IBANs and account numbers, door codes, alarm codes and wifi passwords are encrypted with AES-256-GCM at rest — not merely protected by an access rule.

The same list is withheld from the AI

"Too sensitive to sit in plaintext in the database" and "too sensitive to put in a model's prompt" are treated as one judgement, read from one shared list, so the two can't drift apart later.

You can't grant yourself access

Membership and role are minted server-side. A modified client can't write its own way into a household, because the rules key off the server's claim, never off what the client says about itself.

Default deny

The root rule refuses every read and write that isn't explicitly allowed by name. New collections are locked until someone deliberately opens them.

Money and passwords are not household-wide

Finances are adults-only in a family, admin-only in a business. Shared passwords are admin-only everywhere. A child's login cannot reach either.

In a business, a colleague's record is an HR file

Readable only by the person it describes and by an admin — enforced in the rule itself, so a modified client gets nothing. There is no team directory yet, deliberately: a directory that leaks is worse than no directory.

The reader can't fabricate a quote

When the assistant reads a document back to you, the model returns only character offsets. The server slices the real text out of the real file. There is no path by which it can paraphrase a contract at you and call it a quote.

Hosted in the EU

Cloud Run in europe-west2, built and run from Vienna. Your family's documents don't cross the Atlantic to be stored.

Two things we won't claim. The Content-Security-Policy is currently running in report-only mode while it's tuned, so it is not yet blocking anything — we're not going to describe that as protection. And the activity trail is not an audit log: an entry can't be forged, edited or backdated, but a modified client could fail to write one, so we call it what it is.

Limits

What it won't do.

Most of these were decisions, not omissions. They're the reason the rest of it can be trusted.

It won't tell you what your contract means

It will show you the sentence, exactly as written. Interpreting a document for someone is regulated advice in Austria, where this is built — and being confidently wrong about a lease clause is worse than being no help at all.

It won't read your blood results back to you

A shifted decimal point or a misread reference range on a lab result is harmful in a way a wrong phone number isn't. Medical results are excluded from the reader entirely. Open them on the Medical tab, or ask the doctor who ordered them.

It won't guess

No inventing a name's meaning, no estimating a child's height from a photograph, no filling a blank field with something plausible. If it doesn't know, it asks, or it leaves it out.

It won't write your letter

The "if something happens to me" letter is recorded exactly as dictated — never composed, never improved, never lengthened. It should sound like the person who wrote it.

It won't open anything when you die

There is no mechanism anywhere in this app that keys on a death. A build check fails if any part of the code so much as claims one exists.
